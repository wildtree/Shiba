# 柴犬陣取りゲーム (Shiba Jintori)

柴犬を操作して電柱におしっこをひっかけ、3本の電柱で囲んだ三角形をなわばりにする陣取りゲームです。
.NET 10 + SDL3 (SDL3-CS) で動きます。画像・音声ファイルは使わず、ドット絵も効果音もBGMもすべてコード内で生成しています。

## ビルドと実行

.NET 10 SDK が必要です。SDL3 本体は NuGet パッケージ (SDL3-CS.Windows / SDL3-CS.Linux / SDL3-CS.MacOS) から自動で入ります。

```
dotnet run -c Release
```

配布用の実行ファイルを作る場合 (RID は win-x64 / linux-x64 / linux-arm64 / osx-arm64 など):

```
dotnet publish -c Release -r win-x64 --self-contained
dotnet publish -c Release -r linux-x64 --self-contained
```

## Android版

`android/` にAndroid版があります。ゲームのルール (`World.cs`) や絵の原画 (`SpriteData.cs`) などはPC版と同じファイルを
そのまま使い、描画・入力・音の出口だけをAndroid用に差し替えてあります。SDLは使いません。

必要なもの: .NET SDK の `android` ワークロード (`dotnet workload install android`)、Android SDK、JDK 17以降。

```
dotnet build android/ShibaJintori.Android.csproj -c Release          # ビルド
dotnet build android/ShibaJintori.Android.csproj -t:Install          # つないだ端末/エミュレータへ入れる
dotnet publish android/ShibaJintori.Android.csproj -c Release        # APK を作る
```

APK は `android/bin/Release/net10.0-android/publish/` にできます。

向きは固定していません (端末の「自動回転」の設定に従います)。通知領域はどの向きでもそのまま残ります。
画面の縦横の大きさを見て、フィールドがいちばん大きくなる並べ方を次の3つ (縦・2段・3列) から自動で選びます
(機種ではなく画面の形で決めるので、分割画面などの半端な大きさでも並びます)。

| 並べ方 | 選ばれる画面 | 中身 |
|---|---|---|
| 縦 | スマホの縦、タブレットの縦 | 上にフィールド (横幅いっぱい)、下にステータス領域と、それに重なる半透明の操作パッド |
| 2段 | 広げた折りたたみ (縦持ち・横持ちとも) | 上に PC版とまったく同じ画面 (フィールド + 右のパネル)、下の帯に操作パッド |
| 3列 | スマホの横、タブレットの横 | 真ん中にフィールド (高さいっぱい)、左の列に HUD と十字キー・START/SELECT、右の列に HUD とおしっこ・音・ギブアップ。指がフィールドにかからない |
| テーブルトップ | 折りたたみを半開きにして机に置いたとき (折り目が横) | 折り目でちょうど上下に分け、立っている上の面に画面、寝ている下の面に操作パッド。上の面が横長なら PC版の画面、縦長 (縦に折る小さな折りたたみ) ならフィールドだけを上に出し、ステータスは下の面に出す |

テーブルトップは上の3つより優先します。平らに開いたとき、本のように折り目が縦のときは、ふつうの並べ方に戻ります。
折り目の位置と開き具合は AndroidX の Window ライブラリ (`Xamarin.AndroidX.Window.WindowJava`) で受け取っています。

操作パッドは、スマホの縦画面の幅 (420dp) より大きくはしません。それより広い画面では、
十字キーとおしっこを左右の端へ寄せます (大きな画面は両手で端を持つので、親指が届くように)。

回転や折りたたみの開閉では、アプリを作り直さずに並べ直すだけなので、遊んでいる途中の状態は消えません。
プレイ中に画面の形が変わったときは、持ち替えている間にやられないよう自動でポーズします。

操作パッドは、左が十字キー (指をずらしたまま向きを変えられます)、右がおしっこ (PEE) とギブアップ、
中央が START と SELECT、左上が音の切り替えです (3列のときは上に書いたとおり左右の列に分かれます)。ボタンを押すと軽く振動します
(端末の「タップ時の振動」をオフにしている場合は振動しません)。
端末の「戻る」は、プレイ中はまずポーズになります (もう一度押すとタイトルへ)。

| パッド | 動作 |
|---|---|
| 十字キー | 移動、タイトルでの色えらび、ハイスコア/実績画面、ネーム入力 |
| PEE | 隣の電柱におしっこ、決定 (PC版のスペースキー) |
| START | 決定、プレイ中はポーズ |
| SELECT | タイトルへ戻る。**プレイ中は効きません** (うっかり触って記録が消えないように、START でポーズしてからだけ受け付けます。効かない間は暗く沈んで見えます)。タイトル画面でも効きません |
| GIVE UP | ステージのやり直し。押しまちがい防止のため、2回押しで決まります (1回目は赤く点滅して SURE? になる) |
| 左上の音ボタン | 押すたびに BGM ON (BGMと効果音) → BGM OFF (効果音だけ) → SILENT (マナーモード: 効果音も鳴らさない) と回る。PC版の M キーと同じ |

音の設定は覚えていて、次に起動したときも同じ状態から始まります
(保存先はハイスコアと同じフォルダの `settings.json`)。

音は端末のメディア音量で鳴ります。ゲーム中は音量キーでメディア音量を直接変えられるようにしてあるので、
聞こえないときは音量キーを上げてみてください。操作パッドの左上が「NO SOUND」になっている場合は、
端末側で音の出口を開けられなかったときです (その場合は `adb logcat -s ShibaJintori` に理由が出ます)。

ハイスコアと実績は端末のアプリ専用フォルダに保存されます。アプリを裏に回すと自動でポーズし、音も止まります。

**キーボードとゲームパッド:** Chromebook のキーボードや、Bluetooth / USB でつないだキーボード・ゲームパッドでも遊べます。
キーとボタンの割り当ては PC版と同じです (下の「操作」の節)。F11 はありません。
ただし Esc とパッドの BACK (SELECT) は、画面の SELECT と同じく、**プレイ中はタイトルへ戻らずポーズになります**
(ポーズ中にもう一度押すとタイトルへ戻ります)。タイトル画面で押すとアプリを閉じます。
画面の操作パッドはそのまま表示されるので、タッチとキーを混ぜて使うこともできます。

## Web版 (PWA)

`web/` にブラウザで遊べる版があります。ルール・敵AI・ドット絵・効果音/BGMの合成は PC版をそのまま JavaScript に移したもので、
画面の並べ方と操作パッドは Android版と同じです。ビルドは不要で、外部のライブラリも使っていません。

**置き方:** `web/` の中身を、Webサーバの好きなフォルダにそのままコピーして、そのフォルダの URL を公開するだけです
(例: `https://example.com/games/shiba/`)。どのフォルダに置いても動くよう、パスはすべて相対にしてあります。

- PWA (ホーム画面への追加・オフライン動作) は **HTTPS** で配信したときに有効になります (`localhost` は例外として HTTP でも可)。
  HTTP のサーバや `index.html` を直接開いた場合でも、ゲームはそのまま遊べます (オフライン用のキャッシュが効かないだけ)。
- 一度開くと、ゲームに必要なファイル (19個) が端末にキャッシュされ、以後はネットにつながっていなくても起動します。
- ハイスコア・実績・音の設定はブラウザの `localStorage` に保存します (PC版の JSON と同じ形)。どこにも送信しません。
  サーバ側で何かを記録したり、通信したりするコードはありません。同じサイト (オリジン) に置いた版どうしは記録を共有します。

**更新のしかた:** ファイルを差し替えたら、**`web/version.js` の版番号を必ず変えてください**。
Service Worker はこのファイルの変化で新しい版に気づき、裏で全ファイルを取り直してから、遊んでいる画面に
「新しいバージョンがあります [更新する] [あとで]」と出します (起動時・30分ごと・画面に戻ったときに確認)。
「更新する」で再読み込みして新しい版になります。アプリを閉じて開き直した場合は、知らせなしで新しい版で始まります。
ファイルを足したときは `web/sw.js` の `FILES` にも足してください。

**操作:** キーボードとゲームパッド (Gamepad API) は PC版と同じ割り当てです。違いは次のとおりです。

| キー | 動作 |
|---|---|
| F | フルスクリーン切り替え (F11 はブラウザが使うため) |
| Esc / パッドの BACK | プレイ中はまずポーズ、ポーズ中にもう一度でタイトルへ (ブラウザでは Esc がフルスクリーン解除も兼ねるため) |

スマホやタブレットでは画面に操作パッドが出ます (ほかの端末でも、画面にタッチすると出ます)。
画面の形に合わせて 縦 / 2段 / 3列 の並べ方を自動で選ぶのは Android版と同じです。
テストプレイ用に `index.html?stage=8` で途中のステージから、`?bonus` でボーナスステージから始められます。

| ファイル | 内容 |
|---|---|
| `web/index.html` | 入口 (更新の知らせもここ) |
| `web/version.js` | 版番号。更新のたびに変える |
| `web/sw.js` | Service Worker (オフライン用のキャッシュと更新) |
| `web/manifest.webmanifest`, `web/icons/` | PWA の名前とアイコン |
| `web/js/data.js` | ドット絵・犬種・性格・8x8フォント (`SpriteData.cs` / `Breeds.cs` / `FontData.cs` と同じ) |
| `web/js/world.js` | ゲームのルールと敵AI (`World.cs`) |
| `web/js/app.js` | 画面遷移と描画 (`App.cs` + `AppMobile.cs`) |
| `web/js/gfx.js`, `art.js` | 描画とスプライト |
| `web/js/audio.js` | 効果音とBGMの合成 (Web Audio) |
| `web/js/save.js` | ハイスコア・実績・設定の保存 (`localStorage`) |
| `web/js/input.js`, `pad.js` | キーボード・ゲームパッド・操作パッド |
| `web/js/main.js` | 起動、画面の割り付け、Service Worker の登録 |

## Google Play で配布する

### 1. 配布用の鍵を作る (最初の一度だけ)

ふだんのビルドはAndroidの**デバッグ用の鍵** (`~/.android/debug.keystore`、`CN=Android Debug`) で署名されています。
これは手元や実機で試すためのもので、Playは受け付けません。自分の鍵を作ります。

```
keytool -genkeypair -v -keystore shibajintori-upload.keystore -alias upload -keyalg RSA -keysize 4096 -validity 10000
```

名前やパスワードを聞かれるので、自分で決めて控えておきます。**この鍵ファイルとパスワードは絶対になくさないこと**
(Play App Signing に登録していれば、万一のときは Google 経由で鍵を入れ替えられます)。
鍵は Git に入らないよう `.gitignore` に `*.keystore` / `*.jks` を入れてあります。

次に、`android/signing.props.sample` を同じフォルダに `signing.props` という名前でコピーし、鍵の場所と別名を書きます。
パスワードはファイルに直接書かず、環境変数で渡せます (ひな形がその形になっています)。

```
$env:SHIBA_STORE_PASS = "...."
$env:SHIBA_KEY_PASS   = "...."
```

`signing.props` が無ければ、これまでどおりデバッグ用の鍵で署名されます (手元の実機で試すぶんにはそれで十分です)。

### 2. アップロードするファイルを作る

```
dotnet publish android/ShibaJintori.Android.csproj -c Release
```

`android/bin/Release/net10.0-android/publish/jp.wildtree.android.apps.shibajintori-Signed.aab` ができます。
Playにはこの **.aab** を上げます (arm64 / arm / x86_64 が入っていて、端末ごとに必要なぶんだけ配信されます)。

どの鍵で署名されたかは、次で確かめられます。

```
keytool -printcert -jarfile androidin\Release
et10.0-android\publish\jp.wildtree.android.apps.shibajintori-Signed.aab
```

`CN=Android Debug` と出たら、まだデバッグ用の鍵のままです。

実機に直接入れて確かめたいときは、同じ Release 構成で .apk も作れます。

```
dotnet publish android/ShibaJintori.Android.csproj -c Release -p:AndroidPackageFormat=apk
```

### 3. バージョン番号

`android/ShibaJintori.Android.csproj` の 2 か所です。

| 項目 | 意味 |
|---|---|
| `ApplicationVersion` | Playが見る通し番号。**アップロードのたびに1つ増やす** (同じ番号は受け付けられません) |
| `ApplicationDisplayVersion` | 人が見る版 (`1.0.3` など)。PC版の `ShibaJintori.csproj` の `<Version>` と合わせておく |

### 4. ストア掲載用の画像

`packaging/play/` に入っています。アイコンとフィーチャーグラフィックは `tools/iconmaker` で作り直せます。

| ファイル | Play Console の欄 | 中身 |
|---|---|---|
| `icon-512.png` | アプリアイコン | 512x512 |
| `feature-1024x500.png` | フィーチャーグラフィック | 1024x500 |
| `screenshots/01〜03` | スマートフォン | 縦 (1080x2424): タイトル・ステージ開始・プレイ中 |
| `screenshots/04〜06` | スマートフォン | 横 16:9 (1920x1080): タイトル・プレイ中2枚 |
| `screenshots/foldable/01〜02` | 折りたたみ式デバイス | 広げた内側画面 4:3 (2208x1656、2段の並び): タイトル・プレイ中 |
| `screenshots/foldable/03` | 折りたたみ式デバイス | 広げた内側画面 1:1 (2076x2076) |
| `screenshots/foldable/04` | 折りたたみ式デバイス | 閉じた外側画面 10:16 (1080x1728) |

Play の条件 (2026年11月時点):
- **PNG はアルファチャンネルなしの 24bit**。`adb screencap` の PNG はアルファ付き (32bit) なので、そのままでは使えない。
  上の画像はすべて 24bit に変換済み
- スマホ: 2〜8枚。各辺 320〜3840px、長い辺は短い辺の 2.3 倍まで。縦 9:16・横 16:9 が推奨
- 折りたたみ: 3〜8枚。各辺 960〜3840px。ゲームは「広げた内側 4:3 か 3:4」と「閉じた外側 16:10 か 10:16」を
  最低1枚ずつ。黒い帯や引き伸ばしがないこと
- 通知や通信会社名を写さない。電池・Wi-Fi・電波は満タン表示にする

撮り方: スマホの縦は実機で撮った。横と折りたたみはエミュレータで `adb shell wm size` を
それぞれの縦横比に合わせ、SystemUI のデモモード (時刻 10:00・電池満タン・通知なし) にしてから、
タイトルとデモプレイ (AI が柴犬を動かす画面) を `adb exec-out screencap -p` で撮った。
デモプレイを撮るときだけ、画面の「- DEMO -」「TOUCH THE PAD」を一時的に消したビルドを使っている
(撮影後に元へ戻してある)。

実機で撮るときは通知が画面に出ていないか気をつけてください (通知が重なったまま写り込みます)。

端末に出るアイコンはアダプティブアイコン (`android/Resources/mipmap-*`) で、背景が草の色、前景が柴犬、
テーマアイコン用の白抜きも入っています。これも `tools/iconmaker` の生成物です。

### 5. Play Console で聞かれること

このゲームでの答えは次のとおりです。

| 項目 | 答え |
|---|---|
| データ セーフティ | 収集・共有ともになし。そもそもインターネットの権限を持っていません |
| 権限 | `VIBRATE` (操作パッドの手ごたえ) だけ |
| 広告 | なし |
| アプリ内課金 | なし |
| 対象 API レベル | 36 (Playの下限を満たしています) |
| 64bit 対応 | arm64-v8a を同梱済み |
| プライバシーポリシー | **必須** (集めなくても求められます)。`packaging/play/privacy-policy.html` を公開したURLを貼ります → 下の「6.」 |

コンテンツのレーティングは、アンケートに答えると決まります (暴力・性的表現・ギャンブルのいずれも無しです)。


### 6. プライバシーポリシー

Playは、**データを集めないアプリにもプライバシーポリシーのURLを要求します**
(App content → プライバシー ポリシー の欄)。文面は用意してあります。

| ファイル | 中身 |
|---|---|
| `packaging/play/privacy-policy.html` | 日本語と英語を1枚にまとめたポリシー。どこかのWebサーバに置くだけで動きます |

公開する前に、次の3か所を書きかえてください。

| 書きかえる場所 | 内容 |
|---|---|
| `CONTACT-EMAIL-HERE` (本文に2か所) | 問い合わせ先のメールアドレス |
| `開発者: wildtree` / `Developer: wildtree` | Play Consoleの開発者名に合わせる |
| 最終更新日 (2026年11月18日) | 内容を変えたときに直す |

置き場所は自分のサイトでもGitHub Pagesでも構いませんが、**ログインなしで誰でも開けるURL**である
ことが条件です。そのURLをPlay Consoleの欄に貼ります。

書いてある「何も集めない」の裏づけは次のとおりです。

- 通信するコードが1行もありません (`System.Net`・`HttpClient`・ソケットのいずれも未使用、
  広告や解析のライブラリも入れていません)
- Releaseのマニフェストに入る権限は `VIBRATE` だけで、`INTERNET` がありません。送ろうとしてもできません
  - Debugビルドには高速配置のため `INTERNET` が自動で足されます。Playに出すRelease/AABには入りません
- 保存するのは `hiscores.json`・`achievements.json`・`settings.json` の3つだけで、
  場所は端末内のアプリ専用領域です (他のアプリからは読めず、アンインストールで消えます)

ひとつだけ補足があります。マニフェストが `allowBackup="true"` なので、端末の自動バックアップが
有効だと、このセーブデータがOSの仕組みで**利用者自身のGoogleアカウントのバックアップに含まれる**
ことがあります。開発者が中身を見ることはできず、Playの「データ セーフティ」でも開発者による収集には
当たりませんが、ポリシーにはその旨を書いてあります。気になる場合は `allowBackup="false"` にできます
(そのかわり機種を変えたときにハイスコアが引き継がれません)。

なお、アプリの画面の中にポリシーへのリンクを置くことも求められる場合がありますが、これは
個人情報や機密データを扱うアプリ向けの要件です。このゲームは該当しないので省けます
(入れておきたければタイトル画面に出せます)。

## 配布パッケージの作り方

アイコンは `packaging/icons` にあります (Windows用 `.ico` と、Linux用の 16〜256 ドットの PNG)。

**Windows (Inno Setup 7 64bit版が必要)**

```
powershell -ExecutionPolicy Bypass -File packaging\windows\build-windows.ps1
```

`dist\ShibaJintori-<バージョン>-win-x64-setup.exe` ができます。インストール時に「自分だけ」か「すべてのユーザー」かを選べます。

**Linux (.deb)**

```
bash packaging/linux/build-deb.sh          # x64
bash packaging/linux/build-deb.sh arm64    # arm64
sudo apt install ./dist/shibajintori_<バージョン>_amd64.deb
```

本体は `/opt/ShibaJintori` に入り、`/usr/bin/shibajintori` (起動用スクリプト)、
`/usr/share/applications/shibajintori.desktop`、`/usr/share/icons/hicolor/` 以下のアイコンが置かれます。
パッケージのメンテナ名は環境変数 `MAINTAINER="名前 <メール>"` で指定できます。

バージョン番号は `ShibaJintori.csproj` の `<Version>` を変えると、インストーラと deb の両方に反映されます。

`dotnet run -- --selftest` で、画面を出さずにAI同士を対戦させてルールの動作確認ができます。

## 操作

| キー | 動作 |
|---|---|
| 矢印キー / WASD | 移動 (1マスずつ) |
| スペース / Z / X | 隣の電柱におしっこ (3秒間動けない) |
| P | ポーズ |
| R (ポーズ中) | ギブアップ: そのステージを最初からやり直す (スコアはステージ開始時に戻り、残機はそのまま) |
| M | 音の切り替え (BGMと効果音 → 効果音だけ → 無音、の順に回る) |
| F11 | フルスクリーン切り替え |
| Esc | タイトルへ戻る / 終了 |

Android版の画面の操作パッドは「Android版」の節にあります。Android版でも、キーボードとゲームパッドはこの節と同じ割り当てで使えます。

ゲームパッドにも対応しています (起動後につないでも認識します)。

| パッド | 動作 |
|---|---|
| 左スティック / 十字キー | 移動 |
| A / B / X | おしっこ、決定 |
| Y (ポーズ中) | ギブアップ: ステージをやり直す |
| START | 決定、プレイ中はポーズ |
| BACK (SELECT) | タイトルへ戻る / 終了 |

プレイ中にパッドの接続が切れた場合は自動でポーズします。

SDL がボタン配置を知らない汎用の USB ジョイパッドも使えます。その場合は、軸0/1 (左スティック) とハットスイッチ (十字キー) で移動、
4番目のボタンがやり直し、9番目が BACK、10番目が START、それ以外のボタンはすべて「おしっこ・決定」になります。

タイトル画面では左右キーで柴犬の色 (茶・黒・白) を選べます。しばらく放置するとハイスコア表示 → デモ画面に進みます。

## ルール

- 電柱 3 本におしっこをひっかけると、その三角形の内側が自分のなわばりになる (色が変わる)。面積 1 マスにつき 10 点。
- まだなわばりになっていない電柱は、他の犬の印を上書きできる。上書きされた犬はその電柱をやり直し。
- なわばりになった電柱 (色帯つき) はのっとれないが、新しいなわばりの起点には使える。
- 印をつけた電柱が、ほかの犬のなわばりに取り込まれると、その印は解除される。
- 三角形の内側に他の犬のなわばりが少しでもあると、なわばりは成立しない (辺や電柱で接するだけなら可)。
  3本目のおしっこ中、成立しない三角形は予告線が赤く点滅する。成立しなかった場合は「NO GOOD」と表示され、印は全部取り消されて最初からやり直し。
- なわばりが完成したとき中にいた他の犬は退場 (自分が敵を囲めば +500 点)。
- 自分が敵のなわばりに囲まれる、または車にひかれると残機が減り、なわばり外のどこかに復活する。残機 0 でゲームオーバー。
- 自分以外のなわばりには入れない。
- 得点が 20,000 点に達すると残機が 1 つ増え、その後は 40,000 点ごと (60,000、100,000、…) に増える。
  増えたときは効果音とともに、柴犬の頭上に赤字で「1UP!」と出る。
- フィールドの 3/4 がなわばりになるか、制限時間 (240 秒) が切れるとステージ終了。
  自分の面積が敵のどれか 1 匹より小さければ失敗で、同じステージをやり直し。
- 敵はステージ 1 で 1 匹、ステージごとに 1 匹増えて最大 8 匹。ステージ 4 から道路が 2 本になる。

## 追加要素

- **アイテム (ステージ5から)**: なわばりの外に現れ、12秒で消える (消える前に点滅)。敵も踏めば拾う。
  - 骨: 12秒間、おしっこの時間が半分になる。
  - 忍者の巻物: 10秒間、ほかの犬のなわばりを通り抜けられる (犬が半透明になる)。効果が切れたときに他のなわばりの中にいると、外のどこかへ放り出される (残機は減らない)。
- **雨 (ステージ8から)**: 「RAIN IS COMING!」の予告が5秒出たあと降りだし、その瞬間に、まだなわばりになっていない印が全部流れる。なわばりは残る。
- **ボス犬 (8の倍数のステージ)**: セントバーナード。歩くのもおしっこ (5秒) も遅いが、ほかの犬のなわばりを自由に歩き、
  三角形の中にあるほかの犬のなわばりごと奪い取る。ボスを囲んで退場させると +3000 点。

- **夜のボーナスステージ (4の倍数のステージをクリアした直後。ステージ番号なし)**: 犬たちは眠っていて、動けるのは柴犬だけ。
  60秒間、残機は減らない。なわばりは 1 マス 30 点、眠っている犬を囲むと +2000、全員囲むと PERFECT で +5000。
  ただし 2 マス以内に近づくか、3 マス以内でおしっこをすると犬が目を覚まして逃げる (起きた犬を囲むと +1000。離れるとまた眠る)。
  見えるのは柴犬の周り・印をつけた電柱の周り・自分のなわばりだけ。眠っている犬は「zZ」、起きた犬は光る目で分かる。

出はじめるステージは `World.cs` 冒頭の `ItemFromStage` / `RainFromStage` / `BossEvery` で変えられます。
テストプレイ用に `dotnet run -c Release -- --stage 8` で途中のステージから、`-- --bonus` でボーナスステージから始められます。

## 実績

全24個。タイトル画面で下キー (パッドは十字キー下) を押すと実績画面、上キーでハイスコア画面が開きます。
解除するまで、実績の名前・条件・アイコンは「?」で隠れています。解除するとプレイ中でも画面上部に通知が出ます。
解除状況はハイスコアと同じフォルダの `achievements.json` に保存されます (消すとリセット)。デモ画面では解除されません。

## 敵の犬種の性格

| 犬種 | 性格 |
|---|---|
| コーギー (STEADY) | 足が短くて少し遅いが、用心深く堅実 |
| チワワ (QUICK) | すばしこいがスタミナがなく、ときどき休む。小さななわばりを作りがち |
| シェルティー (HERDER) | 牧羊犬。ほかの犬を囲い込もうとする |
| ハスキー (FIERCE) | 攻撃的。柴犬の近くに陣取り、大きななわばりで囲みに来る。車には無頓着 |
| パグ (LAZY) | のんびり屋。歩くのが遅く、すぐ昼寝する |
| ダルメシアン (RUNNER) | 足が速く遠くの電柱まで走る。道路をあまり気にしない |
| プードル (CLEVER) | 迷いがなく、ほかの犬の印をどんどん上書きする |
| ビーグル (NOSY) | においに夢中。ほかの犬の印に引き寄せられ、気まぐれに寄り道する |

数値は `Breeds.cs` の `Temper` にまとめてあり、そこを変えると調整できます。

## ファイル構成

| ファイル | 内容 |
|---|---|
| `SpriteData.cs` | ドット絵の原画 (文字で描いた 16x16 の絵) |
| `Breeds.cs` | 犬種ごとの配色・耳の形・なわばりの色・性格 |
| `World.cs` | ゲームのルール、敵AI、車 (SDLに依存しない) |
| `App.cs` | 画面遷移と描画 (PC版の起動とイベントループは `#if !ANDROID` の中) |
| `Gfx.cs` | SDL3 描画ラッパー (PC版のみ) |
| `Art.cs` | 全スプライトの組み立て (PC版/Android版で共通) |
| `Input.cs` | キーボードとゲームパッドの入力 (PC版/Android版で共通) |
| `Audio.cs` | 効果音とBGMの合成。音の出口だけ OS ごと (SDL / AudioTrack) |
| `HiScores.cs` | ハイスコア上位 10 件の保存 |
| `Achievements.cs` | 実績の定義・保存・アイコン・解除通知 |
| `SaveData.cs` | セーブデータの保存場所と JSON の読み書き |

Android版のファイル:

| ファイル | 内容 |
|---|---|
| `android/MainActivity.cs` | 入口。向きは端末の設定に従い、回転や開閉で作り直さない。通知領域のぶんの余白。折りたたみの半開き (テーブルトップ) の見張り |
| `android/GameView.cs` | 画面の割り付け (縦・2段・3列を画面の形で選ぶ、半開きなら折り目で分ける) と描画ループ |

| `android/AppMobile.cs` | 縦画面用のステータス領域、横向き (3列) の左右の HUD、Android版の毎フレーム処理 |
| `android/TouchPad.cs` | 半透明の操作パッド (帯に置く・左右の列に分けて置く、絵と指の取り扱い) |
| `android/Haptics.cs` | 操作パッドの手ごたえ (振動) |
| `android/FontData.cs` | 8x8 のドット文字。`tools/fontdump` で SDL の内蔵フォントから作った生成物 |
| `android/SdlShim.cs` | 共通コードが使っている SDL のキー番号だけの置き換え |
| `android/Resources/` | ランチャーアイコン。`tools/iconmaker` の生成物 |
| `android/signing.props.sample` | 配布用の署名の設定のひな形 |

開発用ツール (ゲーム本体のビルドには関わりません):

| ファイル | 内容 |
|---|---|

ハイスコアは Windows では `%APPDATA%\ShibaJintori\hiscores.json`、Linux では `~/.config/ShibaJintori/hiscores.json` に保存されます。
以前のバージョンの `hiscores.txt` / `achievements.txt` があれば、起動時に自動で JSON に移して txt は消します。
